    Perfis psicológicos de jogadores

    A Aula 07 entregou o Labirinto de Moedas com coleta mínima. Agora o Submundo pergunta: para quem esse labirinto é divertido? O modelo psicométrico da Quantic Foundry descreve motivações de jogadores — e hoje vocês adaptam o nível para atrair um perfil.

    Por que jogamos?

    Nem todo jogador busca a mesma recompensa — ação, conquista, história ou descoberta puxam públicos diferentes.

    Quantic Foundry

    Seis clusters de motivação (Action, Social, Mastery, Achievement, Immersion, Creativity) medidos empiricamente.

    Design direcionado

    Escolher o perfil-alvo e configurar mecânicas no Labirinto — não só “tema” ou arte.

    Seis clusters (visão rápida)

    • Action — Destruição, Excitement: impacto imediato, caos controlado, adrenalina.
    • Social — Competition, Community: outros jogadores importam.
    • Mastery — Challenge, Strategy: superar dificuldade e planejar.
    • Achievement — Completion, Power: completar 100%, poder, colecionar.
    • Immersion — Fantasy, Story: mundo, personagem, narrativa.
    • Creativity — Design, Discovery: criar e explorar o que está escondido.

    Destruição / Desafio × Descoberta

    Ação e desafio

    Destruição e Desafio apelam a quem quer tensão, timing e impacto — obstáculos que se movem, riscos, ritmo.

    Descoberta

    Descoberta apela a exploradores — caminhos laterais, segredos, recompensas escondidas.

    Ponte Godot

    Na sala: trilha Ação (obstáculo móvel) ou trilha Conquista (área secreta + moeda brilhante difícil).

    Um labirinto genérico agrada a ninguém de verdade. Escolham um perfil Quantic Foundry, fechem o cercado (uma trilha só) e deixem a mecânica falar pelo público-alvo.

    O foco desta aula (2 encontros)

    Trabalhe sozinho (os dois ofícios) ou convide um colega na Oficina. Na dupla: um faz o Design do perfil, o outro a Programação das mecânicas.

    • Encontro 1 — teoria Quantic Foundry + Camera2D no Player + escolher trilha + esqueleto no Labirinto.
    • Encontro 2 — implementar mecânica, playtest, diário completo e Altar.
    • Continuar o projeto LabirintoDeMoedas — sem pasta sync / Drive no Godot.

    Atividade guiada · 2 encontros · E1 perfil · E2 mecânicas + diário

    Prática — design direcionado

    No Labirinto de Moedas 2D você trabalha sozinho ou em dupla. Escolham uma trilha: Conquista ou Ação.

    Encontro 1 — Perfil + câmera

    Teoria + Camera2D follow + ofícios + trilha Quantic → esqueleto na cena.

    Encontro 2 — Mecânica

    Scripts + playtest: segredo/moeda brilhante ou obstáculo móvel.

    Diário

    Justificar perfil ↔ mecânica — finalize no Encontro 2.

        2. Câmera que segue o Player (Encontro 1)

        Com o mapa maior (segredos, gaps, obstáculos), a vista fixa da Aula 07 não basta. A Camera2D filha do Player acompanha o personagem para vocês desenharem o nível.

├── Sprite2D
├── CollisionShape2D
└── Camera2D          ← novo nesta aula · Enabled / Current

        2. Com a raiz Player selecionada: Add Child Node → Camera2D.
        3. No Inspector da Camera2D: marque Enabled (e Current, se aparecer na sua versão).

        5. (Opcional) Anexe o script do bloco abaixo se a câmera não ativar sozinha.
        6. F5 no cenario.tscn: ao andar, a vista segue o Player.

        3. Trilha Conquista — área secreta + moeda brilhante

        1. Em cenario.tscn, adicione um desvio / gap / altura com uma moeda difícil de alcançar.
        2. No player.gd, acrescente o contador moedas_secretas e a função coletar_moeda_secreta (bloco abaixo) — não apague a coleta da Aula 07.
        3. Na moeda especial: anexe o script de brilho (segundo bloco) ou use moeda-brilhante-exemplo.gd.
        4. Opcional: Area2D ZonaSecreta com body_entered → print("Segredo encontrado!").

        Apoio — Contador secreto (cole no final do player.gd)

        Cole no final do player.gd (depois de coletar_moeda da Aula 07). Contador separado: moedas normais continuam em moedas; as brilhantes usam moedas_secretas. 

        ## --- Aula 08: moedas secretas (acrescente no player.gd) ---
var moedas_secretas: int = 0


func coletar_moeda_secreta() -> void:
	moedas_secretas += 1
	print("Moedas secretas: %d" % moedas_secretas)

        Apoio — Trilha Conquista (cole na moeda especial)

        Anexe à raiz Area2D da moeda difícil. Conecte body_entered → _on_body_entered. A moeda brilhante chama coletar_moeda_secreta (não a coleta comum da Aula 07). 

        extends Area2D
## Aula 08 — moeda brilhante (trilha Conquista)
## Coleta secreta + pulso visual.

@export var pulse_speed: float = 4.0
@export var pulse_amount: float = 0.15

var _base_scale: Vector2 = Vector2.ONE


func _ready() -> void:
	_base_scale = scale


func _process(delta: float) -> void:
	var t := sin(Time.get_ticks_msec() * 0.001 * pulse_speed)
	var s := 1.0 + t * pulse_amount
	scale = _base_scale * s
	modulate = Color(1.0, 1.0, 0.7 + t * 0.3, 1.0)


func _on_body_entered(body: Node2D) -> void:
	if not body.is_in_group("player"):
		return
	if body.has_method("coletar_moeda_secreta"):
		body.coletar_moeda_secreta()
	queue_free()

        Checkpoint Conquista: moeda pulsa · difícil de pegar · some ao coletar · Output mostra Moedas secretas: 1.

        1. Em cenario.tscn, crie Obstaculo (AnimatableBody2D ou CharacterBody2D) + Sprite2D + CollisionShape2D.
        2. Anexe o script do bloco abaixo (movimento vai-e-volta).
        3. Posicione no caminho do Player — timing obrigatório para passar.

        Apoio — Trilha Ação (cole em scripts/obstaculo.gd)

        Cole em scripts/obstaculo.gd anexado à raiz AnimatableBody2D do Obstaculo (não use o script da moeda). Ajuste distance e speed no Inspector. Deixe o obstáculo no ar, sem encravar a colisão no chão. 

        extends AnimatableBody2D
## Aula 08 — obstáculo móvel (trilha Ação)
## Movimento ping-pong no eixo X (sem inverter _dir — evita pisca).

@export var distance: float = 120.0
@export var speed: float = 80.0

var _origin: Vector2
var _traveled: float = 0.0


func _ready() -> void:
	_origin = global_position


func _physics_process(delta: float) -> void:
	_traveled += speed * delta
	# 0 → distance → 0 → … sem teleporte nas bordas.
	global_position.x = _origin.x + pingpong(_traveled, distance)

        Checkpoint Ação: obstáculo vai e volta · Player precisa de timing para cruzar.

        O que NÃO fazer nesta aula

        • Implementar as duas trilhas (escolham uma).
        • Integrar a loja da Aula 06 ou sistema de vidas completo.
        • Abrir o projeto em pasta sync (Drive / OneDrive).

        Pistas secretas do Submundo: nomeie o modelo Quantic Foundry ou uma motivação; diga como o perfil escolhido virou mecânica; e descreva a trilha Conquista (segredo/moeda) ou Ação (obstáculo).

        Diário de desenvolvimento

        Um único diário. Em dupla, os dois escrevem o mesmo texto (autosave). Cada aluno finaliza individualmente no Encontro 2.

        1. Ofícios (Design / Programação, ou “eu nos dois”)
        2. Perfil Quantic Foundry + motivações
        3. Mecânicas da trilha + o que ficou de fora
        4. Playtest — o que o perfil-alvo sente

        Exemplo pronto

        Dupla: Ana (Design do perfil) e Bruno (Programação). Escolhemos Achievement / Descoberta — trilha Conquista. No LabirintoDeMoedas colocamos uma área secreta atrás de um gap e uma moeda brilhante (pulse + coleta). Cortamos loja da Aula 06, combate e multiplayer. No playtest, o perfil de conquista “caça” o segredo; quem só quer correr reto perde a moeda.
